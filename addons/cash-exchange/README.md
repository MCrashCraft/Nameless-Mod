# NamelessMC Cash Exchange

**Unofficial server-only addon, 0.1.0 beta.** Minecraft 1.20.1 / Forge 47.4.16 / Java 17.

Exchange physical **Just Enough Drugz** bills for **NamelessMC Store credits** at **$1 = 1 credit**. The six supported bill values are $1, $5, $10, $20, $50 and $100. This addon is separate from NamelessMC Forge and changes neither the core mod nor the original currency mod.

## Install

1. Keep NamelessMC Forge **0.1.1 or later** and Just Enough Drugz installed on the server. The tested currency release is `JEDZ-1.20.1-v1.2.1.jar`.
2. Add the complete `namelessmc-cash-exchange-1.20.1-0.1.0.jar` to the server's mods folder. Do not install the `-slim.jar`. Clients do not need this addon.
3. Configure the website URL and private key in the existing NamelessMC file, `config/namelessforge/main.yaml`. This addon reads that connection; it never rewrites the core configuration or makes another copy of the key.
4. Start the server. The addon generates `config/namelessexchange-common.toml`. Its `enabled` switch defaults to **false**.
5. As an operator, run `/namelessexchange:exchange admin enable` to allow trades. Run `admin disable` to stop new trades. These commands save the switch and do not require a server restart.

See [CONFIGURATION.md](CONFIGURATION.md) for commands, permissions and receipt recovery. The website needs the Store module and a working add-credits endpoint. Shipping this addon does not configure website products or payment gateways.

## Players

- `/exchange 100` exchanges exactly $100 in eligible bills for **100 Store credits**.
- `/exchange all` exchanges all eligible bills in the main inventory and hotbar.
- `/exchange status` shows the current or most recent exchange receipt.

The guaranteed command name is `/namelessexchange:exchange`; the shorter `/exchange` is registered only if another mod has not already claimed it.

Players must be in survival or adventure mode and have their own active, validated website account with a verified Minecraft integration matching their actual game UUID. Players cannot choose another recipient. No username-only account lookup is used.

Only ordinary, unrenamed, untagged bills in the **36 main-inventory/hotbar slots** are eligible. Wallets, banks, backpacks, offhand and other containers are not scanned. The addon removes an exact combination of existing bills and **does not create change**. If the available denominations cannot make the amount, no bills are taken. Ordinary paper and renamed items cannot masquerade as a bill. The original currency items contain no serial/authenticity data, so genuine bills generated by creative commands or duplicated elsewhere cannot be distinguished by this addon.

## Reliability

A verified website lookup happens before cash is touched. The addon checks the quoted inventory again on the server thread, writes a receipt, removes the selected bills, saves that one player and verifies the saved cash inventory before sending the credit request. HTTP work runs on bounded background workers. Credit amounts are whole integers at the fixed 1:1 rate.

The website credit endpoint has no idempotency token. After an uncertain response or crash, the receipt is **held for staff review**; it is never automatically retried or refunded. Disabling the switch cancels work that has not yet taken cash, while an already submitted exchange still records its outcome. This is conservative recovery, not a claim of exactly-once delivery across a game server and website.

Keep `config/namelessexchange/` with the server's other private state. Do not delete its journal, restore older player files, or roll it back independently of website credits. A world backup cannot undo website credit already granted.

## Verification

30 automated tests passed, including exact bill combinations, inventory/receipt ordering, verified account links, non-retrying transport, ambiguous outcomes, restart recovery, cash slot/item validation, and both pretty-path and index.php API routes. The exact release JAR also passed an isolated Forge 47.4.16 runtime with NamelessMC Forge 0.1.1, official JEDZ and LuckPerms 5.4.102. Real registered test players exchanged six denominations totaling $186 for exactly 186 mock credits. Actual live inventory, the saved player file, native save events and the durable POSTING receipt were checked before the mock response. Disabled mode, invalid links, insufficient cash, modified bills and an explicit LuckPerms denial left cash untouched. An ambiguous HTTP 503 remained held with only one POST, including after configuration reload and a clean restart across two owned JVMs. The switch persisted and both processes exited cleanly. These tests used a separate test-only fixture and a disposable world; the fixture is not part of the release. No real-account credit or production-server test is claimed; final release evidence is recorded with the distribution.
